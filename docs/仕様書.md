# アプリ仕様書：「カグチカ！」

## 1. アプリの名前と目的
### 1.1 アプリ名
**カグチカ！**

### 1.2 アプリの目的
* **伝統文化「石見神楽」の伝達と振興**: ストーリーや成り立ち、社中の背景を分かりやすく伝えることで、観光客や次世代に神楽を身近に感じてもらう。
* **情報の一元化**: 公演情報、座席予約、アーカイブ視聴、AIによるリアルタイム解説など、神楽に関わるすべてのサービスを1つのアプリで完結させる。
* **エンターテインメントを通じたきっかけ作り**: RPGゲームや4コマ漫画などのコンテンツにより、娯楽として楽しみながら神楽の世界に没入し、興味を持つきっかけを提供する。

## 7. 守る条件

1. **技術スタック**:
   * HTML・CSS・JavaScript のみで作成し、データベースおよびログイン機能は作成しない。
2. **ファイル構成と指定**:
   * 画面ごとに独立したHTMLファイルを作成し、トップ画面は `index.html` とする。
   * 全画面で共通の `style.css` および `script.js` を1つずつ使用する。
   * ファイル名・フォルダ名は半角英数字（例: `index.html`）とし、読み込み・画面遷移のパスはすべて `./` から始まる相対パスで記述する。
3. **UI・デザイン方針**:
   * スマートフォンでの閲覧に最適化されたサイズ・レスポンシブ構成とする。
   * 色調は白・黒・灰色を基調とした仮デザインとする。
   * 画像が存在しないエリアは灰色の領域（プレースホルダー）として表現する。
4. **文言・ボタンの指定**:
   * ボタンテキストは遷移図・ワイヤーフレームの指定文言通りとし、カッコ `（ ）` は画面上に出力しない（例: 「（確定する）」→「確定する」）。
   * 画面遷移図に書かれた案内文（「予約完了」等の完了・確定メッセージ）は該当画面内に明記する。
5. **ダミーデータの使用規則**:
   * 実在の人名・地名・施設名・電話番号等は絶対に使用せず、「利用者A」「サンプル町1-1」等の架空と分かる表現を徹底する。

## 8. 確認したいこと（図にない・決まっていないこと）

1. **画面遷移図・ワイヤーフレームに描かれていないボタンの具体的な挙動**:
   * `setting.html`（設定画面）内の「演者1 ON/OFF」「演者2 ON/OFF」「設定1 ON/OFF」「設定2 ON/OFF」の各トグルボタンを押した際の動作（同画面内でスイッチが切り替わる動作でよいか）。
   * `manga_view.html`（漫画表示画面）にある「音量ボタン」等の各種トグル操作の挙動。
   * `rpg_battle.html`（RPGメイン戦闘画面）内の「技1〜4」「攻撃」ボタンを押した際の演出・メッセージ更新動作。
2. **ホームに戻るボタンの共通配置範囲**:
   * 画面遷移図に「エントリーページ（ホーム画面）へはどこからでも戻れる」とあるが、一部のワイヤーフレームで省略されている画面（予約完了、カメラ解説等）にもフッターやヘッダーに固定で「ホームへ戻る」ボタンを配置してよいか。
3. **ガチャ完了・決済完了時の戻り先優先順位**:
   * `payment.html`（決済画面）で確定後、および `gacha_result.html`（結果画面）で確認後の自動遷移先（`gacha_select.html` または `index.html` のどちらを優先するか）。
