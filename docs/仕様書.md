# アプリ仕様書：「カグチカ！」

## 1. アプリの名前と目的

### 1.1 アプリ名
**カグチカ！**

### 1.2 アプリの目的
* **伝統文化「石見神楽」の伝達と振興**: ストーリーや成り立ち、社中の背景を分かりやすく伝えることで、観光客や次世代に神楽を身近に感じてもらう[cite: 39, 40]。
* **情報の一元化**: 公演情報、座席予約、アーカイブ視聴、AIによるリアルタイム解説など、神楽に関わるすべてのサービスを1つのアプリで完結させる[cite: 39, 40]。
* **エンターテインメントを通じたきっかけ作り**: RPGゲームや4コマ漫画などのコンテンツにより、娯楽として楽しみながら神楽の世界に没入し、興味を持つきっかけを提供する[cite: 39, 40]。

## 7. 守る条件

1. **技術構成**:
   * HTML、CSS、JavaScript のみで作成（データベースおよびログイン機能は作成しない）[cite: 39, 40]。
   * 画面ごとに独立したHTMLファイル（トップ画面は `index.html`）とし、共通の `style.css` と `script.js` をそれぞれ1つずつ使用する[cite: 39, 40]。
   * ファイル名・フォルダ名は半角英数字（例: `index.html`）とし、読み込み・画面遷移のパスはすべて `./` から始まる相対パスで記述する[cite: 39, 40]。
2. **デザイン・UI条件**:
   * スマートフォンでの閲覧に最適化されたレスポンシブ構成とする[cite: 39, 40]。
   
   * 画像が存在しないエリアは灰色の領域（プレースホルダー）として表現する[cite: 39, 40]。
3. **文字・データ仕様**:
   * ボタンの文字は遷移図・ワイヤーフレームの表記通りとし、カッコ `（ ）` は含めない（例: 「（確定する）」→「確定する」）[cite: 39, 40]。
   * 画面遷移図記載のメッセージ（「予約が完了しました」「決済が完了しました」等）は該当画面内に明記する[cite: 39, 40]。
   * 実在の人名・地名・施設名・電話番号等は使用せず、「利用者A」「サンプル町1-1」等の架空と分かる表現とする[cite: 39, 40]。

## 8. 確認したいこと（図にない・決まっていないこと）

1. `setting.html`（設定画面）内の「演者1 ON/OFF」「演者2 ON/OFF」「設定1 ON/OFF」「設定2 ON/OFF」等のトグルスイッチを操作した際の具体的な状態保持の挙動[cite: 39, 40]。
2. `rpg_battle.html`（RPG戦闘画面）において「技1〜4」「攻撃」ボタンを押した際の戦闘の勝敗分岐条件（勝ち画面 `rpg_victory.html` / 負け画面 `rpg_gameover.html` への遷移条件）[cite: 39, 40]。
3. `gacha_play.html`（ガチャ画面）における「引く」「10連引く」の実行時の演出の差異、および単一の `gacha_result.html` へ遷移した後の結果表示パターン[cite: 39, 40]。
